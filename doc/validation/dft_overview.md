# Design for testability (DFT) overview

> ⚠️ **Disclaimer:** This document was generated or modified by an AI model. While every effort is made to ensure technical accuracy, the underlying source code and hardware RTL implementation remain the absolute source of truth. Use at your own risk.

> **Intended Audience:** HW Integrators, HW Devs

The CoralNPU IP includes standard Design For Testability (DFT) features to ensure high manufacturing yield and diagnostic visibility. 

## Scan chains

The IP block is synthesized with scan chains enabled. 
- During scan mode, the `te` (Test Enable) pin is asserted, replacing normal functional data paths with scan shift paths. 
- This allows external Automated Test Equipment (ATE) to stream test vectors into the internal flip-flops and observe the combinational logic results.

## Memory BIST (MBIST)

The internal SRAM and Tightly-Coupled Memories (TCM) are wrapped with Memory Built-In Self-Test (MBIST) collars. 
- MBIST controllers can autonomously write and read checkerboard and walking-1s patterns across the memory arrays to detect stuck-at or coupling faults during the manufacturing test process.

## Debug interface (JTAG/DM)

The CoralNPU supports a standard RISC-V Debug Module (DM) accessible via JTAG. This interface provides non-intrusive halt/resume capabilities and allows the reading of architectural state, serving both software debugging and post-silicon validation.
