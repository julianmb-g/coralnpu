# Vector backend decoder (DE2)

> **Intended Audience:** HW Devs, SW/Compiler Devs

The Vector Backend Decoder represents the secondary decode stage (DE2) in the RVV execution pipeline. It is responsible for translating the unified logical command (`LCMD_t`) into discrete, executable micro-operations (`UOP_QUEUE_t`) that can be scheduled across the execution units.

## Micro-operation expansion from lcmd_t

The primary scalar-to-vector interface passes instruction data that the initial decode stage parses into the `LCMD_t` struct (defined in `hdl/verilog/rvv/inc/rvv_backend.svh`). This structure centralizes:

- The base instruction encoding (`RVVCmd`)

- The effective element widths (`EEW_e` for `vs1`, `vs2`, `vd`)

- The effective vector multipliers (`EMUL_e`)

- The explicit vector length (`evl`) and `vstart` offsets

The secondary decode stage (`hdl/verilog/rvv/design/rvv_backend_decode_de2.sv`) processes this `LCMD_t`. Based on the specific `vtype` configuration, execution unit mapping (e.g., ALU, LSU, PMT), and the total element count, the `rvv_backend_decode_ctrl` logic expands a single `LCMD_t` into one or multiple `UOP_QUEUE_t` packets.

These micro-operations are subsequently pushed into the `uop` queue where they await arbitration and structural hazard checks before being dispatched to physical vector paths.
