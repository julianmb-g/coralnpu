## Overview

The debug module implements a subset of the RISC-V Debug Specification, providing external debug support for the CoralNPU core. It allows a debugger to halt, resume, and single-step the core, as well as read and write core registers and memory.

## Architecture

The debug module is a standalone module that connects to the core via a dedicated debug interface. It communicates with an external debugger through a simple request/response protocol.

## Round-Robin Debug Request Arbitration and Response Routing

The CoralNPU implements a 2-port Round-Robin Arbiter (`CoralNPURRArbiter`) at the debug module's input boundary. This arbiter multiplexes requests from two distinct sources:

1.  **Source 0:** The external debugger interface (`io.dm.req`).
2.  **Source 1:** The internal memory-mapped CSR interface (`csr.io.debug.req`).

When a request is granted by the arbiter, its source ID (`dmReqArbiter.io.chosen`) is pushed into a single-entry **Inflight Response Routing Queue** (`inflight = Module(new Queue(UInt(1.W), 1))`).

This inflight queue preserves the origin of the currently executing command. When the debug module generates a response, the `rspId` is dequeued from the inflight queue to route the response back to the requester:

- If `rspId === 0.U`, the response is routed to the external debugger (`io.dm.rsp`).
- If `rspId === 1.U`, the response is routed to the internal CSR interface (`csr.io.debug.rsp`).
