## Overview

> [!IMPORTANT]
> The Level 1 Instruction (L1I) and Data (L1D) caches (`L1ICache.scala` and `L1DCache.scala`) described in this document are **dormant and uninstantiated** in the production CoralNPU IP block. The IP block is AXI4-native and utilizes Tightly Coupled Memories (TCMs) along with a dedicated L0 Fetch cache for its primary memory hierarchy. These L1 cache modules are maintained in the repository strictly as **reference code** and architectural templates for SoC vendors requiring custom, non-native cache hierarchies.

## Reference Cache Architecture (Uninstantiated)

While not part of the active CoralNPU IP, the reference cache designs illustrate a potential mapping of 256-bit external AXI4 data widths to the core's internal data paths.

### Cache Coherence (Architectural Principle)

The CoralNPU architecture natively **lacks a hardware cache coherence protocol** (such as MESI or snooping mechanisms). In configurations where caches are enabled, software is strictly responsible for managing memory consistency. Data must be explicitly managed using hardware flush interfaces or software-level synchronization primitives to prevent stale reads.

### FlushState FSM (ADR-115)

The L1 Data Cache implements a dedicated Finite State Machine (`FlushState`) to handle software-initiated cache flush operations. This FSM ensures that all dirty cache lines are evicted and synchronized with main memory before acknowledging the flush command.

The FSM transitions through the following states:

- **`sNone`**: The default idle state. A flush operation is triggered when a valid flush request is received, transitioning the FSM to `sCapture`.
- **`sCapture`**: Captures the current state of the cache tags and valid bits to determine which lines require flushing. Transitions to `sProcess`.
- **`sProcess`**: Iterates through the captured lines. If a dirty line is found, it transitions to `sMemwaddr` to initiate an AXI4 write. If all lines are processed, it transitions to `sAxiresp` to await final AXI4 write responses.
- **`sMemwaddr`**: Drives the AXI4 write address channel (`AW`) for the dirty line eviction. Transitions to `sMemwdata`.
- **`sMemwdata`**: Drives the AXI4 write data channel (`W`) with the cache line contents. Transitions to `sAxiready`.
- **`sAxiready`**: Waits for the AXI4 slave to accept the write data. Once accepted, it loops back to `sProcess` to evaluate the next line.
- **`sAxiresp`**: Waits for the final AXI4 write response (`B` channel) to ensure all inflight evictions are globally visible. Transitions to `sEnd`.
- **`sEnd`**: Asserts the flush ready signal (`io.flush.ready`) to notify the software that the flush is complete. It then returns to `sNone` once the host acknowledges the completion.

This FSM guarantees that flush operations are serialized and that no new memory transactions are initiated until the flush completes, enforcing strict memory consistency during the operation.

## Reference Interfaces

- **IBus/DBus**: Designed to connect to the core's instruction and data buses.
- **AXI4**: Designed to interface with external system memory using 256-bit data width and 32-bit addressing.
