# Command Ring Buffer

The CoralNPU utilizes a command ring buffer mechanism to decouple scalar-side command submission from vector-side execution. This structure enables asynchronous command processing and buffers high-latency operations.

## Overview

The command ring interface serves as the primary software-hardware gateway for vector instructions. The software subsystem writes commands into memory-mapped command rings, and the NPU fetches these commands to the vector instruction queue, managed by the `RvvFrontEnd`.

## Interface

The software writes commands to a circular buffer defined in [TCM](../microarch/tcm.md). The hardware uses a set of pointers to manage the ring:
- **Head Pointer**: Updated by software as commands are enqueued.
- **Tail Pointer**: Updated by NPU hardware as commands are consumed.

## Synchronization

Synchronization between the software enqueuing commands and the hardware consuming them is primarily managed through software manipulation of the head and tail pointers, combined with appropriate memory ordering guarantees provided by the system. The CoralNPU hardware does not appear to implement specific hardware barrier instructions or pipeline flush mechanisms dedicated to the command ring. Software must ensure that writes to the command ring are visible to the hardware before updating the head pointer, typically using memory fence instructions on the scalar core if necessary.

## Implementation Details

The ring buffer is implemented using [MultiFifo](../microarch/common/multi_fifo.md) structures for command staging.
